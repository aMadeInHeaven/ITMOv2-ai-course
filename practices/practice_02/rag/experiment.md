# RAG
# Эксперимент: подготовка tests_load.md по RAG-промту

## Цель
Сформировать файл tests_load.md с 5 нагрузочными сценариями, используя ограниченный набор источников и фиксируя evidence из TRAINING_PR.diff.

## Источники (ограниченные)
1. TRAINING_PR.diff (evidence строки)
2. problem.md (метрики, числа — если недоступны, отмечаем как best practice)
3. tests_integration.md (риски)
4. tests_e2e.md (согласование сценариев)

## Правила из промта (rag.md)
- Используем только 4 источника.
- Каждое число — из problem.md или помечено как best practice.
- Каждый риск — из tests_integration.md или problem.md.
- Каждый сценарий — согласован с tests_e2e.md.
- Каждая строка в таблице содержит evidence вида file:line из TRAINING_PR.diff.

## Подход
1. Определяем ключевой эндпоинт: POST /api/reviews (см. TRAINING_PR.diff, app/api.py:35-38).
2. Учитываем бизнес-логику сервиса обзоров (см. TRAINING_PR.diff, app/review_service.py:19-22).
3. Формируем 5 сценариев с метриками p50/p95, 2xx rate, размер ответа, ошибочные ответы, устойчивость к всплескам.
4. Каждый сценарий указывает один основной источник (problem.md, tests_integration.md или tests_e2e.md) и evidence из diff.

## Результат
- Создан файл tests_load.md с 5 сценариями и колонками: Сценарий, Нагрузка, Предел, Что измеряем, Источник, Evidence.
