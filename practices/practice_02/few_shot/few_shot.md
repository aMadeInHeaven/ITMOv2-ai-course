# Техника: Few-shot

## Цель
Улучшить tests_load.md, показав AI два примера (хороший и плохой) нагрузочного теста, чтобы он сгенерировал новые сценарии по образцу.

## Промт

Ниже два примера нагрузочных тестов для FastAPI-эндпоинта.

### Хороший пример

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Параллельные запросы | 10 rps, 5 мин, 50 воркеров | p95 < 500 ms; 5xx = 0% | p50/p95 latency, доля 5xx | app/api.py:35-38 |
| Превышение размера | 1 запрос с diff 150 KB | 413 Payload Too Large | Код ответа, время до отказа | app/api.py:36-38 |

### Плохой пример

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Большой diff | Отправить большой diff | Не должен падать | Время | app/api.py |

### Задача

На основе этих примеров и метрик из problem.md:
- P95 latency <= 500 ms (без LLM)
- Доля 2xx >= 99%
- Размер diff <= 100 KB (TO BE)

Сгенерируй 3 новых строки нагрузочных тестов для tests_load.md:
1. Параллельная нагрузка (10 rps, 5 минут)
2. Таймаут LLM (заглушка задерживается на 60 сек)
3. DoS через неожиданные типы (payload не dict)

Каждая строка должна иметь evidence file:line из diff.

## Ожидаемый результат
tests_load.md с 5 сценариями и конкретными числами.

## Как проверить
- [ ] Есть числа (rps, ms, KB, %)
- [ ] Есть ссылки на метрики problem.md
- [ ] Каждая строка = evidence file:line
- [ ] Нет выдуманных фактов вне diff
