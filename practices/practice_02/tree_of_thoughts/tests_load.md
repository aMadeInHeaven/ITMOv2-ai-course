# Нагрузочные тесты: Сбалансированный план (5 сценариев)

## Цели и метрики

- Цели: убедиться, что система выдерживает ожидаемую нагрузку, предсказуемо деградирует при пиках, корректно обрабатывает таймауты и большие полезные нагрузки, а также масштабируется при параллельных запросах.
- Метрики: p95/p99 latency, throughput (RPS), error rate, timeout rate, CPU/Memory утилизация (если доступно), успешность сценариев.

## Воспроизводимость

- Фиксируем версии инструментов и профили сценариев.
- Для каждого сценария: указываем параметры (RPS, длительность, размеры), начальные условия и критерии приемки.

---

## Сценарий 1: Baseline стабильной нагрузки

- Параметры: RPS = 50, длительность = 10 мин, равномерный поток.
- Что проверяем: стабильность на номинальной нагрузке.
- Критерии приемки: p95 < 200 мс, error rate < 0.5%.

## Сценарий 2: Всплеск (burst) и эластичность

- Параметры: ступенчатый профиль 50 -> 150 RPS (1 мин), затем 150 -> 50 RPS.
- Что проверяем: поведение при резких пиках и восстановление.
- Критерии приемки: p99 < 500 мс в пике, восстановление p95 < 200 мс за 2 мин, error rate < 1%.

## Сценарий 3: Таймауты и медленные зависимости

- Параметры: инжектируем задержки/таймауты в зависимости или используем профиль с увеличенным latency.
- Что проверяем: корректную обработку таймаутов, ретраи/политику отказов.
- Критерии приемки: timeout rate контролируемый (< 2%), деградация предсказуемая, нет каскадных отказов.

## Сценарий 4: Большие payload'ы / размеры ответов

- Параметры: нагрузка с увеличенным размером запросов/ответов (например, 2-5 МБ).
- Что проверяем: влияние IO/сети и лимитов на производительность.
- Критерии приемки: p95 < 400 мс, error rate < 1%, отсутствие OOM/ throttling.

## Сценарий 5: Параллельность/конкурентность

- Параметры: конкурирующие клиенты (например, 100 одновременных соединений) при 80 RPS.
- Что проверяем: contention, блокировки, пул соединений.
- Критерии приемки: p95 < 300 мс, отсутствие deadlock, стабильный throughput.

---

## Обоснование выбора

Сценарии покрывают ключевые риски, описанные в problem.md, при умеренных трудозатратах и с явной привязкой к метрикам. Это соответствует альтернативе C (сбалансированной) из `tree_of_thoughts.md`.
