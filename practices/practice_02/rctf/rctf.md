# Техника: RCTF (Role, Context, Task, Format)

## Цель
Переписать tests_load.md, явно разделив роль AI, контекст, задачу и формат, чтобы получить более структурированный результат.

## Промт

**Role:**
Ты — инженер по нагрузочному тестированию FastAPI-сервисов с опытом в LLM-интеграциях.

**Context:**
Есть эндпоинт POST /api/reviews (app/api.py:35-38), который:
- принимает dict payload
- обращается к payload["diff"] без валидации
- вызывает ReviewService.review → LLM.generate без таймаута (app/review_service.py:19-22)

Метрики из problem.md:
- P95 latency <= 500 ms (без LLM)
- Доля 2xx >= 99%
- Размер diff <= 100 KB (TO BE)

**Task:**
Заполни tests_load.md так, чтобы:
1. Было минимум 5 сценариев нагрузки
2. Каждый сценарий имел числа (rps, ms, KB, %)
3. Каждый сценарий проверял конкретный риск из problem.md
4. Были указаны пороги отказа (когда скейлить)
5. Каждая строка имела evidence file:line из diff

**Format:**
Markdown-таблица:

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|

Плюс после таблицы — раздел "Пороги отказа" с 3 пунктами.

## Ожидаемый результат
tests_load.md с 5+ сценариями, порогами отказа и evidence.

## Как проверить
- [ ] Роль явно указана
- [ ] Контекст содержит ссылки на diff
- [ ] Задача декомпозирована на 5 пунктов
- [ ] Формат соблюдён (таблица + пороги)
