# FocusBoard — макет сценария

Текстовый макет в Markdown открывается прямо в репозитории. Он показывает, где на экране находятся форма, список и обратная связь на каждом шаге. Студент может создать учебную задачу, найти её в каталоге, открыть подробности, изменить статус или удалить задачу.

## 1. Главная страница `/`

```text
FocusBoard
Study planner

┌─ Add a task ───────────────────┐  ┌─ Study tasks ──────────────────┐
│ Title*                 [     ] │  │ All tasks                       │
│ Subject*               [     ] │  │ No tasks yet.                   │
│ Due date*              [     ] │  └─────────────────────────────────┘
│ Priority*              [ ▾ ]   │
│ Description (optional) [     ] │
│ [ Add task ]                   │
└────────────────────────────────┘
```

При загрузке вместо **No tasks yet.** показаны индикатор и **Loading tasks…**. На узком экране форма остаётся первой, список располагается под ней.

## 2. Ввод

```text
┌─ Add a task ─────────────────────────────────┐
│ Title*    [ Review thermodynamics          ] │
│ Subject*  [ Physics                        ] │
│ Due date* [ 2026-11-27                     ] │
│ Priority* [ High                          ▾] │
│ Description (optional) [ Reread notes      ] │
│ [ Add task ]                                 │
└──────────────────────────────────────────────┘
```

Если поле пропущено или некорректно, под ним появляется пояснение. Например, **Enter a title.** Фокус переходит к первому полю с ошибкой. Дату на самом экране браузер показывает в своём локальном формате. Для срока выбирают сегодняшнюю местную дату или более позднюю. **Description (optional)** принимает многострочный текст и может оставаться пустым.

## 3. Отправка

```text
┌─ Add a task ─────────────────────────────────┐
│ Title*    [ Review thermodynamics          ] │
│ Subject*  [ Physics                        ] │
│ Due date* [ 2026-11-27                     ] │
│ Priority* [ High                          ▾] │
│ Description (optional) [ Reread notes      ] │
│ [ Adding task… ]  ◌                          │
└──────────────────────────────────────────────┘
```

Поля и кнопка временно недоступны. **Adding task…** — состояние кнопки во время POST. **Loading tasks…** в панели списка относится к GET.

## 4. Успех

```text
┌─ Add a task ───────────────┐  ┌─ Study tasks ─────────────────── All tasks ─┐
│ Пустые поля формы          │  │ ┌─────────────────────────────────────────┐ │
│ [ Add task ]               │  │ │ Review thermodynamics  [High priority]  │ │
│ ✓ Task added.              │  │ │ Physics                                 │ │
└────────────────────────────┘  │ │ Due Nov 27, 2026                        │ │
                                │ │ [ Mark completed ]                      │ │
                                │ └─────────────────────────────────────────┘ │
                                └─────────────────────────────────────────────┘
```

Карточка отображает сохранённую сервером запись. Заголовок ведёт к деталям. У приоритета есть текстовая метка. В заголовке панели **Study tasks** расположена ссылка **All tasks**.

## 5. Ошибка и повтор

```text
┌─ Add a task ──────────────────────┐ ┌─ Study tasks ─────────────────────┐
│ Введённые значения                │ │ Could not load tasks.   [ Retry ] │
│ [ Add task ]                      │ └───────────────────────────────────┘
│ Could not add task.     [ Retry ] │
└───────────────────────────────────┘
```

Здесь показаны оба возможных сообщения. **Retry** в форме повторяет POST с текущими данными, а **Retry** в списке повторяет GET.

## 6. Каталог `/tasks`

```text
FocusBoard
Study planner

[ Dashboard ]
All tasks
[ Priority: High ▾ ]  [ Status: Active ▾ ]  [ Due date: This week ▾ ]

┌─ Physics ──────────────────────────────────────────┐
│ Review thermodynamics         [High priority]      │
│ Physics                       Due Nov 27, 2026     │
│ [ Mark completed ]                                 │
└─────────────────────────────────────────────────────┘
```

Карточки разбиты по предметам. Фильтры применяются одновременно, а их выбор виден в адресе, например `/tasks?priority=high&status=active&due=week`. Для пустого каталога показано **No tasks yet.** Если записи есть, но ни одна не соответствует фильтрам, показано **No tasks match these filters.** При загрузке виден **Loading tasks…**, при сбое — **Could not load tasks.** и **Retry**. На узком экране фильтры располагаются друг под другом.

## 7. Детали `/tasks/:id`

```text
[ Назад к задачам ]
┌─────────────────────────────────────────────────────┐
│ Review thermodynamics                               │
│ Physics                                             │
│ [Active] [High priority]                            │
│ Due Nov 27, 2026                                    │
│ Description                                         │
│ Reread notes                                        │
│ Solve two problems                                  │
│ [ Mark completed ]   [ Удалить задачу ]             │
└─────────────────────────────────────────────────────┘
```

Если описание пропущено, видно **No description.** Переход по названию карточки доступен с клавиатуры. Ссылка **Назад к задачам** открывает главную страницу с формой создания задачи. При загрузке виден индикатор **Loading task**, HTTP 404 показывает **Task not found.**, сбой чтения — **Could not load task.** и **Retry**.

## 8. Статус задачи

**Mark completed** доступна на главной, в каталоге и в деталях. Во время запроса действие для этой задачи блокируется. После успеха появляется метка **Completed**, заголовок в списках зачёркивается, а кнопка меняется на **Mark active**. Это действие возвращает задачу в Active. Фильтр статуса учитывает сохранённый результат. При ошибке видны **Could not update task status.** и **Retry**, статус остаётся прежним.

## 9. Подтверждение удаления

```text
┌──────────────────────────────────────────────┐
│ Точно хотите удалить?                       │
│ Review thermodynamics                       │
│            [ Отмена ] [ Удалить навсегда ]   │
└──────────────────────────────────────────────┘
```

**Удалить задачу** открывает диалог с фокусом на **Отмена**. Отмена закрывает диалог, сохраняет задачу и не отправляет DELETE. **Удалить навсегда** отправляет запрос и блокирует обе кнопки на время ожидания. При успехе приложение возвращает в каталог с прежними фильтрами, задача исчезает. При сбое диалог показывает **Could not delete task. Try again.**, после чего можно подтвердить повторно или отменить.

## Как использовался AI

OpenAI Codex участвовал в проектировании, реализации и подготовке тестов. Ниже приведены примеры формулировок задач, которые отражают выполненную работу.

- **Макет.** «Спроектируй экран FocusBoard для студента. Покажи исходный пустой список, ввод учебной задачи, ожидание, успешное добавление и ошибку с повтором. Предусмотри размещение формы над списком на узком экране». Codex предложил две панели и отдельную обратную связь для каждой. После сверки с кодом в макете уточнены подписи кнопок, разделены GET и POST, показаны сброс формы при успехе и сохранение значений при ошибке. Экспорт макета — этот Markdown-файл.
- **Интерфейс.** «Реализуй форму и список на React и TypeScript. Переиспользуй MUI `TextField`, `Paper`, `Button`, `Alert`, `CircularProgress` и `Chip`. Подключи GET и POST к Express и примени общую тему». При проверке уточнили проверку календарной даты по формату API и защиту от повторной отправки до перерисовки React. Также добавили объединение задач по `id`, чтобы поздний ответ GET сохранял уже показанный результат POST.
- **Тесты.** «Предложи проверки видимого поведения в React Testing Library. Подмени ответы GET и POST с сохранением структуры JSON через MSW. Проверь пустой список, задержку, ошибки, Retry и ровно один POST при наложении событий отправки». В тесте успеха сделали заголовок в ответе отличным от введённого, чтобы проверить источник данных карточки. Тест повторной отправки проверяет нативную блокировку кнопки независимо от CSS MUI и отдельно создаёт два события `submit` до перерисовки. При временном отключении синхронной защиты этот тест зафиксировал два POST и упал. После восстановления защиты тест снова прошёл.

- **Расширение сценария.** «Добавь каталог с группировкой по предметам и фильтрами в URL, детали с описанием, обратимое выполнение и подтверждение удаления». Codex добавил переходы и состояния запросов. При проверке уточнили возврат к той же комбинации фильтров и начальный фокус на **Отмена**. Тест отмены проверяет ноль запросов DELETE, тест успешного удаления — возврат к отфильтрованному списку. Тесты с задержанными ответами проверяют, что изменение статуса переживает переходы между экранами и поздний PATCH не восстанавливает удалённую задачу. [Тесты каталога](../src/AllTasksPage.test.tsx), [тесты действий](../src/TaskActions.test.tsx)
