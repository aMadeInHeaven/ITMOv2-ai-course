# FocusBoard

FocusBoard — планировщик учебных задач. Он помогает студенту быстро записать задание, не пропустить deadline, увидеть дела на сегодня и неделю, а затем отметить или удалить выполненную задачу.

Проект выполнен для практики 8 «Добавляем фронтенд к своему проекту с помощью AI».

## Основной сценарий

Пользователь — студент, которому нужно организовать учебные задачи.

1. Открывает Overview и видит ближайшие дела и сводку.
2. Нажимает кнопку «Добавить задачу» в правом нижнем углу.
3. Заполняет название, тему, deadline, приоритет и, при необходимости, описание.
4. Клиент валидирует данные и отправляет POST /api/tasks.
5. После успешного ответа появляется уведомление, а задача отображается в нужной подборке.

Также пользователь может открыть карточку задачи, отфильтровать общий список, изменить статус Completed / Active и удалить задачу после подтверждения.

## Интерфейс и маршруты

Слева всегда остаётся навигация, текущая вкладка выделена.

| Раздел | Что показывает |
| --- | --- |
| Overview | Сводку, прогресс и задачи на ближайшие дни |
| My day | Только задачи с deadline на сегодня |
| Week tasks | Задачи текущей недели |
| All tasks | Все задачи, категории и фильтры |
| Completed | Выполненные задачи |

Карточка задачи содержит статус приоритета: low — зелёный, medium — жёлтый, high — красный. На странице деталей видны тема, описание, deadline, приоритет и статус. После просмотра, изменения статуса или удаления приложение возвращает пользователя на исходную вкладку.

## Валидация, состояния и доступность

- Название обязательно и не может состоять из пробелов.
- Deadline не может быть раньше текущей локальной даты.
- Описание ограничено 1000 символами; показан счётчик и ошибка при превышении.
- Перед созданием похожей задачи выводится предупреждение о возможном дубликате.
- При закрытии изменённой формы без сохранения запрашивается подтверждение.
- Удаление задачи требует подтверждения в диалоге.
- Пользователь видит загрузку, пустой список, успех, ошибку и Retry.
- Во время отправки форма блокируется: двойной клик или повторный Enter не создают второй запрос.
- У полей есть подписи и сообщения ошибок; фокус заметен, элементы доступны с клавиатуры.
- На ширине 375 px интерфейс остаётся доступным.

## Технологии

- React 18 и TypeScript — клиент.
- Material UI (MUI) 6 — Button, TextField, Dialog, Paper, Chip, Alert и CircularProgress.
- React Router — маршрутизация.
- Express — API.
- data/tasks.json — локальное JSON-хранилище.
- Vitest, React Testing Library, user-event и MSW — клиентские тесты.
- Supertest — тесты Express API.

Единые цвета, типографика и настройки фокуса заданы в src/theme.ts. Общие стили и адаптивная раскладка находятся в src/styles.css.

## Запуск

Требуются Node.js 22+ и npm.

    npm ci
    npm run server

После сборки приложение доступно по адресу http://127.0.0.1:3001/. Один Express-процесс раздаёт интерфейс и API, поэтому прямые переходы по маршрутам работают.

Для разработки во втором терминале:

    npm run dev

Vite откроется по адресу http://localhost:5173/ и передаст запросы /api в Express.

## API

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | /api/tasks | Список задач |
| POST | /api/tasks | Создаёт задачу |
| GET | /api/tasks/:id | Возвращает одну задачу |
| PATCH | /api/tasks/:id | Меняет completed |
| DELETE | /api/tasks/:id | Удаляет задачу |

Задача содержит id, title, subject, description, dueDate, priority, completed и createdAt.

## Макет и участие AI

Текстовый прототип находится в docs/prototype.md. В нём отражены исходный экран, ввод задачи, загрузка, успех и ошибка.

Для проектирования, реализации и подготовки тестов использовался OpenAI Codex:

- предложил первоначальный макет и состояния пользовательского сценария;
- помог реализовать компоненты React на базе MUI и подключить их к Express API;
- предложил проверки React Testing Library с подменой ответов API через MSW.

После ручной проверки были изменены навигация, модальная форма, возврат на исходную вкладку, валидации, подтверждения действий, цвета приоритетов и тестовые ожидания. AI не заменял ручную проверку: все сценарии проверялись в работающем приложении.

## Тесты

Запуск всех тестов:

    npm test

Проверка типов и production-сборка:

    npm run build

Клиентские тесты используют MSW: тестовые GET, POST, PATCH и DELETE возвращают тот же формат JSON, что и настоящий Express API, и не изменяют пользовательский файл data/tasks.json.

| Требование практики | Где проверяется |
| --- | --- |
| Повторная отправка не создаёт второй запрос | src/TaskForm.test.tsx — blocks overlapping submissions while the create request is pending |
| Отображение и взаимодействия | AddTaskDialog.test.tsx, AppShell.test.tsx, AllTasksPage.test.tsx, TaskActions.test.tsx |
| Валидация формы | TaskForm.test.tsx: обязательные поля, дата, лимит описания, дубликаты |
| Загрузка, пустой список, успех, ошибка, Retry | App.test.tsx, TaskForm.test.tsx, TaskDetailsPage.test.tsx |
| Полный сценарий от действия до результата | TaskForm.test.tsx — posts the task values, announces success, and renders the returned task |
