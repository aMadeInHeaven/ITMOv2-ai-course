# Логика «Избранные котики (Лайки)» — черновик спецификации

## 1. Модель данных и хранилище

- Ключ в `localStorage`: `cat-meme-favorites:v1`.
- Структура данных в хранилище: JSON-массив строковых идентификаторов карточек, без дубликатов. Пример: `["card-123", "card-456"]`.
- Порядок массива соответствует порядку добавления (стабильный, без пересортировки).
- В оперативной памяти: внутренний `Set<string>` как кэш для проверки статуса в O(1). Кэш синхронизируется с массивом перед записьью в `localStorage` и при внешних изменениях.
- Лимит записей: максимум 50 ID. Попытки добавить сверх лимита отклоняются.
- Версионирование: суффикс `:v1` в ключе; миграции в будущих версиях выполняются через новый ключ.

## 2. Публичный API модуля

- Подход: инкапсулированное состояние (store) поверх `localStorage`, плюс чистые утилиты сериализации/валидации внутри модуля.
- Фабрика стора: `createFavoritesStore(options?) => FavoritesStore`.
  - `options.key?: string` — ключ в хранилище, по умолчанию `cat-meme-favorites:v1`.
  - `options.max?: number` — лимит ID, по умолчанию `50` (диапазон 1–50).
  - `options.storage?: Storage` — целевое Web Storage, по умолчанию `window.localStorage`.

Экспортируемые методы `FavoritesStore`:

- `getIds(): string[]` — получить текущий снимок списка избранного.
- `has(id: string): boolean` — проверить, находится ли ID в избранном. Время выполнения: O(1) за счёт внутреннего `Set`.
- `add(id: string): { ok: boolean, reason?: "invalid_id" | "exists" | "limit_exceeded" | "storage_quota_exceeded" }` — добавить ID. При успехе генерируется событие изменения.
- `remove(id: string): { ok: boolean, reason?: "invalid_id" | "not_found" | "storage_quota_exceeded" }` — удалить ID. При успехе генерируется событие изменения.
- `toggle(id: string): { ok: boolean, added?: boolean, reason?: "invalid_id" | "limit_exceeded" | "storage_quota_exceeded" }` — переключить статус ID (добавить, если не было; удалить, если было). При успехе генерируется событие изменения.
- `clear(): { ok: boolean }` — очистить избранное (память и хранилище). Генерируется событие сброса.
- `size(): number` — текущее количество элементов (из кэша).
- `reloadFromStorage(): { ok: boolean, reason?: "corrupted_storage" }` — принудительно перечитать и валидировать хранилище, пересобрать внутренний `Set`, сгенерировать событие синхронизации.

Принципы:

- Методы изменяют состояние только после успешной записи в `localStorage`. При ошибке квоты или иных исключениях состояние откатывается к предыдущему.
- Валидация входных данных обязательна перед любым изменением.
- Утилиты сериализации и валидации — чистые функции, стора — инкапсулированное состояние.

## 3. Обработка ошибок и краевые случаи

- Ошибка квоты хранилища (`QuotaExceededError`):
  - Возникает при `setItem`. Модуль ловит исключение, откатывает локальные изменения, возвращает `reason: "storage_quota_exceeded"` и генерирует событие ошибки.
  - Состояние в памяти и на диске остаётся консистентным (предыдущая версия).

- Некорректный ID:
  - Входной ID должен быть непустой строкой длиной 1–64 символа, соответствующей шаблону `^[A-Za-z0-9_-]{1,64}$`.
  - При несоответствии модуль не выполняет запись, возвращает `reason: "invalid_id"`.

- Повреждённый JSON в `localStorage`:
  - При `reloadFromStorage()` и инициализации, если `JSON.parse` падает или структура не является массивом строк без дубликатов, модуль выполняет восстановление: формирует пустой массив, пересобирает кэш и пытается перезаписать корректное значение.
  - Если при восстановлении возникает `QuotaExceededError`, запись пропускается, кэш остаётся пустым, генерируется событие ошибки.
  - Генерируются события: ошибка (`corrupted_storage`) и изменение (`clear` с источником `recovery`).

- Лимит:
  - При попытке добавить 51-й элемент модуль возвращает `reason: "limit_exceeded"` и не меняет состояние.

- Дубликаты:
  - `add` при наличии ID возвращает `reason: "exists"` и не записывает.
  - `remove` при отсутствии ID возвращает `reason: "not_found"`.

## 4. События и синхронизация

- Канал уведомления: `CustomEvent` на `window`.
- Имена событий и `detail`:
  - `favorites:change` — изменение состава избранного.
    - `detail`: `{ action: "add" | "remove" | "toggle" | "clear" | "sync", id?: string, ids: string[], source: "local" | "remote" | "recovery" }`.
  - `favorites:error` — ошибки стора/хранилища.
    - `detail`: `{ type: "storage_quota_exceeded" | "corrupted_storage" | "invalid_id", id?: string, message?: string }`.
  - `favorites:ready` — стора инициализирован, доступен снимок.
    - `detail`: `{ ids: string[] }`.

- Синхронизация между вкладками:
  - Прослушивание события `storage` на `window`. При изменении ключа `cat-meme-favorites:v1` модуль перечитывает, валидирует данные, обновляет кэш и генерирует `favorites:change` с `source: "remote"` и действием `sync`.
  - При получении некорректных данных по `storage` применяется стратегия восстановления, как описано выше.

## 5. Нефункциональные требования

- Валидация аргументов: обязательна для всех публичных методов. Проверяются типы, диапазоны и формат ID; опции фабрики (`key`, `max`, `storage`) валидируются (непустой ключ, `max` в диапазоне 1–50, объект `Storage`).
- Производительность:
  - `has` — O(1) за счёт `Set`.
  - `add`, `remove`, `toggle` — O(1) на операцию с кэшем; сериализация и запись массива в `localStorage` — O(n), где `n ≤ 50`, что допустимо.
  - `getIds` — O(n) с копированием массива.
- Безопасность и надёжность:
  - Пользовательские данные (ID) не попадают в `innerHTML`; модуль работает только с идентификаторами.
  - Защита от прототип-поллюции: из `localStorage` принимаются только массивы простых строк, не объекты.
  - Все записи в хранилище выполняются атомарно на уровне операции `setItem`; при ошибках состояние откатывается.
- События синхронны относительно успешной операции записи, чтобы избежать гонок и упрощать подписчикам реакцию на изменения.
