# Рефлексия по практике «Две фичи с агентом»

## 1. Что помогло
- **Правило из AGENTS.md о запрете innerHTML:** агент строго следовал правилу безопасной работы с DOM и использовал `textContent` и `document.createElement`, что исключило XSS-уязвимости при вводе пользовательских данных.
- **TDD-скилл (`cat-card-tdd`):** помог декомпозировать фичи на конкретные сценарии (A1 для ленты, B1/B3 для валидации и `localStorage`). Четкая фаза RED (ожидаемое падение) не позволила агенту выдать ложноположительный результат.
- **Собственный MCP-сервер (`cat-cards`):** предоставил агенту готовую схему проверки данных (`prepare_cat_card`), благодаря чему логика валидации в UI и тестах получилась согласованной.
- **Автоматический Hook (`check-after-edit.js`):** давал мгновенную обратную связь после сохранения файлов, запуская `scripts/check.mjs`.

## 2. Что мешало
- **Вложенная структура монорепозитория:** так как Git-корень находился на уровне всего репозитория курса (`ITMOv2-ai-course`), при создании Git Worktree агент запутался в относительных путях и случайно создал дублирующую вложенную папку `practices/practice_04/...`, что сломало резолв ES-модулей в `vitest`.
- **Специфика CLI OpenCode:** команда `opencode reload` в CLI воспринимается как аргумент пути, а не слэш-команда чата `/reload`, что потребовало ручной регистрации MCP через `opencode mcp add`.

## 3. Где пришлось вмешаться человеку
- **Исправление файловой структуры и импортов:** удаление ошибочно созданной агентом вложенной папки `practices/`, выравнивание путей импорта в `tests/feature-b.test.js` и синхронизация `package.json`.
- **Контроль слияния и изоляции:** проверка отсутствия регрессий в Фиче А после реализации Фичи B и безопасный fast-forward merge ветки `practice-04-b`.
