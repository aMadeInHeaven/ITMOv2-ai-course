# Рефлексия

Главное наблюдение этой практики: подключение инструмента само по себе ещё не означает, что он работает. В исходном `opencode.json` MCP был помещён в дополнительный объект `servers`. JSON выглядел правдоподобно, но не соответствовал схеме OpenCode, где именованные серверы должны лежать непосредственно внутри `mcp`. После исправления конфигурации я добавил интеграционный тест с настоящим дочерним процессом — он проверяет handshake, discovery, валидный вызов, опасный URL и неизвестный tool. Это полезнее проверки текста конфигурации.

Второе наблюдение касается дублирования правил. Когда браузерная форма и MCP валидируют одну сущность отдельно, ограничения быстро расходятся. Общий модуль `src/card-validation.mjs` сделал единым контракт длины полей и допустимых протоколов. Unit-тесты теперь проверяют эту функцию, а MCP-тест показывает, что тот же контракт работает через JSON-RPC.

Третье наблюдение появилось во время визуальной проверки. Атрибут `hidden` на кнопке очистки был перекрыт CSS-правилом `.button { display: inline-flex; }`, поэтому пустое действие оставалось видно на мобильном экране. Автоматическая сборка эту проблему не заметила; реальный просмотр на ширине 390 px заметил. Исправление `[hidden] { display: none !important; }` стало хорошим напоминанием, что функциональные тесты и визуальная проверка отвечают на разные вопросы.

Skill оказался полезен не как длинная памятка, а как узкий маршрутизатор: он включается только для задач каталога и фиксирует несколько инвариантов, которые легко случайно нарушить. Hook дополняет его короткой обратной связью после редактирования, но полный runner остаётся явной финальной проверкой — это предсказуемее, чем надеяться только на автоматический запуск.
