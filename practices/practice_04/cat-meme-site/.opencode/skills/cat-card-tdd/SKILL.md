# Cat Card TDD

Разрабатывай каталог через проверяемые пользовательские сценарии. Источник требований — [сценарии приёмки](references/acceptance-scenarios.md); визуальные решения сверяй с `docs/style-guide.md`.

## Неподвижные ограничения

- Не вставляй пользовательские строки через `innerHTML`; создавай узлы через DOM API и записывай текст через `textContent`.
- Принимай для изображения только абсолютные `http:` и `https:` URL.
- Каждому изображению нужен содержательный `alt`; при ошибке загрузки заменяй его элементом с `role="img"` и доступной подписью.
- Пользовательские карточки храни под ключом `cat-meme-cards:v1`. Повреждённые данные не должны ломать страницу.
- Общую валидацию держи в одной функции, чтобы браузер и MCP применяли одинаковые правила.

## Рабочий цикл

1. Выбери один сценарий из файла приёмки и добавь тест, который наблюдает поведение, а не формулировку реализации.
2. Запусти `npm test` и убедись, что новый тест падает по ожидаемой причине.
3. Внеси минимальное изменение в `src/` или `index.html`, не ослабляя ограничения выше.
4. Запусти `npm run check`. Если менялись правила карточки или MCP, проверь и допустимый, и опасный ввод.

Не останавливайся на зелёном unit-тесте: итоговая проверка должна включать сборку и настоящий JSON-RPC обмен с MCP-процессом.
